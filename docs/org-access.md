# Демо и приостановка организации

Ограничения обратимые: строка в `org_access` на одну организацию. Таймера нет, внешней лицензии нет, данные и пароли команда не удаляет и не меняет. Пока строки нет, организация в полном режиме и не приостановлена. Установка API создаёт пустую таблицу и не заполняет её.

Системный админ — роль `admin` (учётка Максима). Роль `owner` — хозяин фирмы. На него демо и приостановка действуют так же, как на менеджера. Роли в таблице `users` эти команды не переписывают.

## Что делает демо

Для всех, кроме `admin`, на сервере:

- `GET/POST /api/users` и `PATCH /api/users/{id}/role` — отказ. Пригласить админа или сменить себе роль нельзя.
- PDF КП (и просмотр, и `download=1`) — отказ.
- Каталог: `limit` больше 40, `offset` больше 0, параметры `export` / `format` / `download` / `dump` — отказ. В обычной странице до 40 позиций закупочная цена не отдаётся.
- Список правил каталога и их запись — отказ. Подсказки совместимости в конфигураторе остаются.
- В одном КП или оценке не больше 40 позиций фурнитуры.

`admin` в той же организации ходит как раньше, в том числе когда организация приостановлена.

## Что делает приостановка

На каждом защищённом запросе читается база, не кука. Уже открытая сессия сотрудника получает отказ. Работают вход, выход, `GET /api/auth/me`, смена своего пароля, витрина (`/api/vitrine/chat`, `/api/vitrine/leads`), `/api/health`, `/api/templates`. Вход Максима (`admin`) не закрывается.

Чужая организация этой строкой не затрагивается. В теле `PATCH /api/org/access` поле `org_id` игнорируется: меняется только организация сессии.

Журнал: `org_access_mode` (`full -> demo` или обратно) и `org_suspend` (`active -> suspended` или обратно). В строке есть `actor_id`, `org_id` и `created_at`.

## Включение на VDS

С этой машины на VDS не заходят. Команды выполняет тот, у кого уже есть доступ к серверу. Сначала посмотреть, какая организация чья. Не считать slug `default` организацией Александра, пока в списке не видно его email и роль `owner`.

```bash
cd /var/www/dushevye
PYTHONPATH=/var/www/dushevye /var/www/dushevye/venv/bin/python -m app.org_access \
  --db /var/www/dushevye/data/app.db status
```

В выводе id, slug, имя, режим, и пользователи: id, роль, email. Пароли не печатаются.

Дальше сухой прогон (ничего не пишет), подставив цифры и адреса из `status`:

```bash
PYTHONPATH=/var/www/dushevye /var/www/dushevye/venv/bin/python -m app.org_access \
  --db /var/www/dushevye/data/app.db enable-demo \
  --org-id ID \
  --confirm-slug SLUG \
  --confirm-owner-email EMAIL_АЛЕКСАНДРА \
  --actor-email maxim59901@gmail.com \
  --ack-admins ЧИСЛО_АКТИВНЫХ_ADMIN
```

`--ack-admins` должен совпасть с числом активных `admin` в этой организации. Если хозяин случайно заведён как `admin`, команда остановится: для `--confirm-owner-email` нужна роль `owner`. Пока в списке лишний admin, демо его не ограничит.

Запись — та же команда с `--apply` в конце. Повторный `--apply` не плодит журнал, если режим уже `demo`.

Приостановка и возврат — отдельные команды с теми же подтверждениями: `suspend`, `resume`, `disable-demo`.

Из кабинета это же делает только `admin`: блок «Доступ организации» на `/lk/admin.html`, `PATCH /api/org/access` с `X-CSRF-Token`.

После выкладки кода нужен перезапуск `dushevye-api`, иначе старый процесс флаги не читает. `catalog.db` при выкладке не заменяется. `python -m app.seed --force-password` не запускать.

## Откат

```bash
PYTHONPATH=/var/www/dushevye /var/www/dushevye/venv/bin/python -m app.org_access \
  --db /var/www/dushevye/data/app.db disable-demo \
  --org-id ID --confirm-slug SLUG \
  --confirm-owner-email EMAIL --actor-email maxim59901@gmail.com \
  --ack-admins N --apply
```

И `resume`, если включали приостановку. Либо в кабинете админа: режим «Полный» и снять «Доступ приостановлен». Пользователи, проекты, КП и каталог остаются.

## Выкладка, которая не снимает уже закрытые файлы

`install-on-vds.sh` затирает nginx файлом `deploy/nginx-dushevye.conf` и скрипт бэкапа. В конфиге уже есть отказ для точечных путей и для расширений bak, sql, sqlite, db, env, если после них точка, слэш или конец адреса (`index.html.bak.20260101` тоже). `/media/` без `alias` и без `^~`: иначе такой location обходит отказ. Обычные картинки `/media/...jpg` отдаются из `root`.

Копии `index.html.bak.*` установка больше не кладёт в `public/`. Уже лежащие там переносятся в `/var/backups/dushevye/pre-deploy/` (каталог `700`).

`catalog.db` в payload быть не должно: `deploy-vds.py` такой архив не заливает, install живой файл не копирует.

Бэкап один: `/etc/cron.d/dushevye`. Строка `dushevye-backup.sh` из root crontab снимается, прочие строки crontab сохраняются. sshd install не трогает. Архив бэкапа `600`, каталог `700`, базы внутри — снимок SQLite.

## Остаточный риск

Оценка стекла, которую экран показывает после входа, — уже посчитанное число. Делить его на площадь и сравнивать прозрачное с матовым можно. Таблицы ставок и коэффициентов в браузере и в ответе `/api/config/estimate` нет. Прятать их обфускацией бессмысленно: страница обязана показать итог.

В демо хозяин по-прежнему видит цены строк того КП, которое сам собрал (не больше 40 позиций). Полный прайс каталога списком, постранично и файлом PDF с этой организации для него закрыт. `admin` прайс видит.

Лимиты шаблонов (мин/макс проёма) по-прежнему публичные: без них витрина и конфигуратор не показывают поля. Пороги петель и пары фурнитуры остаются на сервере; наружу уходят только тексты ошибок.

Печать экрана (`window.print`) печатает то, что уже нарисовано. Это не отдельная выгрузка файла.

Репозиторий публичный. Ставки стекла лежат в `app/quotes.py` и читаются тем, у кого есть доступ к GitHub. Это не пароль и из истории git не вычищается.
