# Версии и аудит

## Требование

На каждой сущности (КП, товар, проект, склад, документ) — история изменений: кто, когда, что было / стало.

## Видимость лога (зафиксировано)

| Роль | Видит лог | Деньги / закуп / наценка |
|------|-----------|---------------------------|
| Хозяин (Максим + партнёр) | Полный | Да |
| Админ | Полный | Да (видит закуп и наценку) |
| Менеджер | Только свои | Нет (склад: смотрит и резервирует) |
| Бухгалтер | Только свои | Да (счета, акты; видит закуп и наценку) |
| Замерщик | Только свои | Нет |
| Монтажник | Только свои | Нет |
| Снабжение | Только свои | Закупки/поставщики; видимость цен — по матрице |
| Производство | Только свои | Нет |

## Роль учётки

Тип учётки задаётся при регистрации (роль в приглашении). Меняют админ/хозяин.

## Статус

Два журнала, оба в `app.db`:

- `audit_log` — события без диффа полей: вход, выход, пароль, приглашение, смена роли, `quote_create`, `project_create`, `project_status_change`, `stock_in` / `stock_out` / `stock_reserve` / `stock_release`. `GET /api/audit` отдаёт их как раньше. Админ и хозяин видят всю организацию, остальные роли — только свои строки.
- `entity_versions` — снимок ключевых полей до и после. Отката и слияния нет, строки только читаются.

`GET /api/versions` (CSRF не нужен; без сессии 401). Параметры: `entity_type` (`project`, `quote`, `stock`, `user`), `entity_id` вместе с типом, `limit`. Видимость та же: admin и owner — вся организация, остальные — только `actor_id` равный себе. В ответе `before`, `after` и короткая строка `summary`.

Пишется при создании проекта, смене статуса (повтор того же статуса пропускается), привязке КП, сохранении КП, движении склада (остаток, резерв, минимум) и смене роли. В снимок КП не входят закуп и суммы.

## События воронки проектов

- `project_create` — создан проект (в деталях имя клиента и номер КП, если его указали сразу).
- `project_status_change` — смена статуса, в деталях подписи шагов: `Создан -> Просчёт`. Повтор того же статуса запись не добавляет.

## События склада

Пишутся в тот же `audit_log`, `target_type=stock`, `target_id` — `part_id` каталога. В деталях артикул, количество и номер проекта, если движение к нему привязано.

- `stock_in` — приход.
- `stock_out` — расход свободного остатка.
- `stock_reserve` — резерв.
- `stock_release` — снятие резерва.
