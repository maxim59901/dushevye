> Проект «Станок». Витрина + конфигуратор КП + ЛК (личный кабинет).
> Источник фронтенда: `http://178.212.15.231/` (nginx 1.24.0 / Ubuntu).
> Репозиторий создан из снапшота продакшена.

## 0. Статус репозитория (05.11.2026)

**GitHub — источник правды.** В репозитории полный стек, не только ранний фронтенд:

```
public/     витрина, cfg.html, ЛК
app/        FastAPI + SQLite (auth, пользователи, аудит, каталог)
parsers/    импорт комплектующих
docs/       роли, auth, парсеры, бэкапы
deploy/     nginx, systemd, install-on-vds.sh, deploy-vds.py
data/       CSV и parts.json (файлы *.db в git не входят)
```

Корневые `index.html`, `cfg.html` и `lk/` перенесены в `public/` — так их отдаёт nginx. Этот файл остаётся в корне.

**P1 безопасность (#2–6) в коде.** CSRF на login / logout / смене пароля / приглашении / смене роли; лимит входа 5 попыток / 15 минут → 429; cookie HttpOnly и SameSite=Strict (Secure только при `DUSHEVYE_COOKIE_SECURE=1`, после HTTPS); CSP в `deploy/nginx-dushevye.conf`; временный пароль в модалке, не в `alert()`. Секрет сессии только из `DUSHEVYE_SESSION_SECRET` (`api.env` не коммитится). HTTPS и домен в этот шаг не входят. Пароли учёток и пароль VDS в git не попадают.

Разделы ниже — разбор раннего фронтенд-снапшота. Где стек «неизвестен» или «бэкенда нет в git», смотрите раздел 0: бэкенд уже в `app/`.

## 1. Обзор проекта

**Назначение:** производство и продажа душевых ограждений под проём для дилеров и монтажных бригад. Ключевой функционал — конфигуратор чернового коммерческого предложения (КП) с расчётом стоимости по типу конструкции, размерам проёма, стеклу и фурнитуре.

**Тип:** статический фронтенд (HTML/CSS/JS) в `public/` + API на FastAPI (`app/`, префикс `/api/*`).

**Роли пользователей (8):** Админ, Хозяин, Бухгалтер, Менеджер, Замерщик, Монтажник, Снабжение, Производство.

## 3. Текущая архитектура

### 3.1 Фронтенд

- **Чистый HTML/CSS/JS** — без фреймворков, без сборщика, без модулей.
- **Стили:** инлайн `<style>` в каждом файле + общая `lk.css`. CSS-переменные для темы.
- **JS:** инлайн `<script>` в каждом файле. `auth.js` — общий хелпер (fetch к API, guard страниц, chrome).
- **Адаптивность:** медиа-запросы на 900px/1000px/1100px. Печать (print CSS) для КП.
- **API-клиент:** `Auth.api()` — fetch с credentials, JSON body, обработка ошибок.

### 3.2 Бэкенд (`app/`, FastAPI + SQLite)

Код API в репозитории. На VDS nginx проксирует `/api/` на uvicorn. Эндпоинты:

| Эндпоинт | Метод | Назначение |
|---|---|---|
| `/api/auth/me` | GET | Текущий пользователь |
| `/api/auth/login` | POST | Вход |
| `/api/auth/logout` | POST | Выход |
| `/api/auth/change-password` | POST | Смена пароля |
| `/api/users` | GET/POST | Список / создание пользователей |
| `/api/users/:id/role` | PATCH | Смена роли |
| `/api/audit` | GET | Журнал действий |
| `/api/catalog` | GET | Каталог комплектующих (фильтры, пагинация) |
| `/api/stock` | GET | Остатки склада (группа, производитель, поиск) |
| `/api/stock/in` `/out` `/reserve` `/release` | POST | Приход, расход, резерв, снятие резерва |

Стек: Python, FastAPI, SQLite (`DUSHEVYE_DB`, отдельно `DUSHEVYE_CATALOG_DB`). Nginx только раздаёт статику и проксирует API.

### 3.3 Конфигуратор КП (cfg.html)

- Шаблоны: угловая (две стенки), прямая ниша (1–2 створки), П-образная, трапеция. Правила размеров и фурнитуры проверяет сервер.
- Размеры проёма в мм по полям шаблона (A/B/C, высота, для трапеции угол).
- Стекло: 8/10 мм, прозрачное/матовое, толщина из допуска шаблона.
- Фурнитура: выбор позиций из `GET /api/catalog` (группа, производитель, поиск). Цена строки — `price` из API.
- Расчёт площади стекла по типу (упрощённая формула) и ставки `GLASS_RATES` в `cfg.html` — оценка, не прайс стекла.
- Печать/PDF через `window.print()`.

## 4. Сильные стороны

1. **Чистый, минималистичный дизайн** — единая цветовая схема, CSS-переменные, адаптивность.
2. **Ролевая модель** — 8 ролей с разграничением доступа, privileged (admin/owner).
3. **Каталог комплектующих** — фильтрация по производителю/группе/поиску, карточки с фото, цены закупа (скрыты по умолчанию).
4. **Конфигуратор КП** — рабочий расчёт с печатью PDF.
5. **Аудит-лог** — журнал действий.
6. **Управление пользователями** — приглашения, смена ролей.
7. **Без зависимостей** — нет npm, нет сборщика, простой деплой.

## 5. Проблемы и слабые места

### 5.1 Архитектура

| # | Проблема | Критичность |
|---|---|---|
| 1 | **Нет сборщика/модулей** — весь JS инлайн, дублирование кода между страницами | Средняя |
| 2 | **Нет шаблонизатора** — HTML копируется, изменения требуют правки в 10+ файлах | Высокая |
| 3 | **Нет тестов** — ни unit, ни e2e | Высокая |
| 4 | **Нет CI/CD** — деплой ручной | Средняя |
| 5 | **Нет версионирования API** — эндпоинты без `/v1/` префикса | Низкая |
| 6 | **Нет документации API** — нет Swagger/OpenAPI | Средняя |

### 5.2 Безопасность

| # | Проблема | Критичность |
|---|---|---|
| 1 | **CSRF** — включён на login, logout, смене пароля, приглашении и смене роли | Закрыто в коде |
| 2 | **Rate-limit** на `/api/auth/login` — 5 попыток / 15 минут, ответ 429 | Закрыто в коде |
| 3 | **Пароли в alert()** — временный пароль в модалке с кнопкой «Копировать» | Закрыто в коде |
| 4 | **Нет HTTPS** — сайт работает по HTTP (IP без домена). Secure-cookie выключен, пока нет TLS | Высокая |
| 5 | **Нет CSP (Content Security Policy)** | Средняя |
| 6 | **XSS-риск** — `innerHTML` с пользовательскими данными в каталоге (частично экранируется через `esc()`) | Средняя |
| 7 | **Нет валидации на клиенте** — формы не проверяют email/телефон | Низкая |
| 8 | **Cookie** — HttpOnly и SameSite=Strict. Secure включается переменной `DUSHEVYE_COOKIE_SECURE` после HTTPS | Частично |
| 9 | **Нет 2FA** для привилегированных ролей | Низкая |

### 5.3 Функциональность

| # | Проблема | Критичность |
|---|---|---|
| 1 | **Конфигуратор: стекло всё ещё оценка** — фурнитура уже из каталога, ставки стекла зашиты в `GLASS_RATES` | Средняя |
| 2 | **Сохранение КП** — черновик в `app.db`, привязка к проекту через `projects.quote_id` | Закрыто в коде |
| 3 | **PDF КП** — сервер отдаёт BOM (`fpdf2`). Логотипа и реквизитов ещё нет; экранный черновик по-прежнему печатается через `window.print()` | Низкая |
| 4 | **Каталог: нет CRUD** — только чтение, нет добавления/редактирования позиций | Высокая |
| 5 | **Привязка КП к проекту** — из `cfg.html` и из карточки `/lk/projects.html`. Полный цикл заказа (замер, цех, монтаж) ещё впереди | Средняя |
| 6 | **Нет уведомлений** — нет email/SMS при смене статусов | Средняя |
| 7 | **Нет поиска по сайту** | Низкая |
| 8 | **Нет мультиязычности** (только русский) | Низкая |

### 5.4 UX/UI

| # | Проблема | Критичность |
|---|---|---|

## 7. Рекомендации по приоритетам

1. **Безопасность прежде всего** — HTTPS, CSRF, rate-limit, Secure cookies. Без этого нельзя пускать реальных пользователей.
2. **Прайс стекла** — фурнитура КП уже из каталога; ставки стекла в `GLASS_RATES` всё ещё оценка.
3. **КП к клиенту** — черновик и PDF уже в `app.db`, проект с клиентом и статусом — в `projects`. Дальше замер, цех и монтаж.
4. **Мобильная навигация** — дилеры и монтажники работают с телефонов.
5. **Убрать захардкоженные данные** — дашборды должны показывать реальные цифры.

## 8. Технический долг

- 10 HTML-файлов с дублированной разметкой (header, sidebar, footer).
- CSS дублируется между `lk.css` и инлайн `<style>` в каждом файле.
- JS дублируется — каждая страница имеет свой инлайн-скрипт.
- Нет единого точки входа для JS-модулей.
- Временный пароль больше не показывается через `alert()` (модалка в `auth.js`).
- `innerHTML` без санитизации в нескольких местах.
